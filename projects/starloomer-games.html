Four games. One CORE.
A station in glorious disrepair.

Starloomer Mini Games CORE is an original, interconnected suite of four browser-based sci-fi games built for Carrier Channel 116. Crew progression, resource economies, station condition and event history flow through one shared world rather than four disconnected demos.

The central design

Players aren't just earning isolated high scores. They work for a fictional, catastrophically mismanaged pirate broadcasting station. Every derelict, repair job, intercepted signal and arcade mission can alter the shared crew economy or push a common station project forward.

The design intentionally crosses gameplay genres: choice-based salvage, collective station management, radio intelligence, asymmetric cooperative troubleshooting, and real-time asteroid combat. Different games contribute to the same story.

The uploaded Mini Games CORE v0.4 source includes four FastAPI game services, a shared Python core module, and an SQLite database using WAL mode. The archived working database and player records are not published as part of this portfolio.

The actual mechanics

The games you built—not generic concepts.

01 / JUNK RUN · SALVAGE + STATION CONTROL

Salvage your way out of a broadcast disaster.

The original Junk Run interface doubles as Carrier Channel 116's station dashboard. It tracks Broadcast Integrity, Station Power, Engineering, Hull Integrity, Communications, Crew Morale, and the notorious Management Confidence. Crew can load a persistent profile, allocate stats, equip gear, launch choice-based salvage missions, review activity, and contribute recovered material toward collective station projects.

Projects such as Restore Auxiliary Transmitter C, Robot Mobility Project, and Repair Dock 3 consume Scrap, Electronics, and Weird Junk, then unlock station improvements, achievements or downstream gameplay. That's the entire joke: the team must keep a chaotic live broadcast running with whatever junk it can find.

02 / ENGINEERING PANIC · COOPERATIVE JARGON MENACE

Space Team meets the Retroencabulator.

Not a generic ship-repair clicker. Engineering Panic is a deliberately incomprehensible communications game. A team of two to four players receives different banks of toggle switches, breakers, rotary selectors, patch panels and pushbuttons. One player is instructed to operate a device that exists on someone else's console—and must communicate the ridiculous instruction through Engineering Comms.

The control labels are procedural technobabble such as “PAN-DIRECTIONAL RETROPHASIC COUPLER” and “SIDE-FUMBLING ARRESTOR.” A correct operation advances the recovery sequence and adds four stability. Mistakes subtract nine stability and three seconds from the two-minute clock. Successful recovery can unlock a triple-reward deep-salvage mission for Junk Run.

Shared state architecture

Actions in one game change the others.

SIGNAL SWEEP → discovers derelict location ↓ JUNK RUN → salvages location / delivers resources ↓ CORE → creates engineering recovery opportunity ↓ ENGINEERING PANIC → team restores systems ↓ CORE → grants deep-salvage opportunity ↓ JUNK RUN → 3× reward / guaranteed equipment drop SPACE ACE → separate arcade action; crew XP, cargo and records ↓ SHARED CORE (crew · equipment · station · achievements)

Prototype vs public deployment: The original four-service version uses FastAPI and one canonical SQLite CORE on a trusted local host. GitHub Pages cannot serve that Python backend. BuiltByCal currently offers browser-adapted Space Ace and Signal Sweep, a simplified Junk Run demonstration, and descriptive material for Engineering Panic. The original project DB, accounts, historical crew records and private server are not uploaded here. A secure standalone CORE API would be required for fully shared public multiplayer.

What this shows technically

Schema design, shared resource ownership, Python service boundaries, persistent state, asynchronous event-driven UI, complex game rules, client/server integration, real-time game rendering, cooperative interaction design and converting ridiculous narrative premises into working software.

The source archive also includes launch scripts, setup documentation, playtest guidance and a prototype database. The portfolio describes and demonstrates the systems while keeping the original database private.
